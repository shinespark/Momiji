# Momiji: 自分用 macOS 日本語 IME 設計書

## 背景と目的

普段は Dvorak 配列で、DvorakJP 系のローマ字テーブルを読み込んだ Google日本語入力を使っている。不満は次の2つ。

- 変換候補を選ぶたびに数字キーへ指を伸ばす必要があり、ホームポジションから手が離れる
- ホームポジションで候補を選べる IME があっても QWERTY（`a s d f …`）前提で、Dvorak では使えない

Momiji は、この2点を解決する自分専用の IME。変換中の操作感は mozc（Google日本語入力）と同じにする。特に、ライブ変換はせず、スペースで明示的に変換する。

自分だけが使う。配布はしない。

## 成功の条件・失敗の条件

- 成功: Google日本語入力の代わりに毎日使い続けられる
- 失敗（アンチゴール）: 変換精度が低いこと。精度が低ければ Google日本語入力に戻る。機能が揃っていても精度で負ければ失敗とみなす

変換精度を最優先にする。

### 精度の判断

- 実装の最初の段階で、AzooKeyKanaKanjiConverter + Zenzai + DvorakJP Prime のローマ字テーブルだけで変換を試せるものを作る。候補ウィンドウやキー操作の作り込みより前に置く
- この段階で実際に打ってみて、続けるかどうかを決める
- Google日本語入力より精度が低いとわかったときは、手を打つ前に報告して相談する（私の判断）

## ゴール

1. ホームポジションのキーで変換候補を選んで即確定できる（Dvorak と QWERTY を切り替えられる）
2. Google日本語入力形式のローマ字テーブル（DvorakJP Prime）を読み込める
3. mozc の「ことえり」風キー設定と同じ操作で変換できる（文節の区切り直し、文字種変換など）
4. Tab での予測変換と、入力中の自動サジェストがある
5. 設定画面がある

## ノンゴール

- ライブ変換
- iOS 版、配布用パッケージ、公証（notarization）
- ユーザー辞書（後回し）
- Momiji の中の英数モード（英字は OS の入力ソース切り替えで打つ）
- azooKey 用ローマ字テーブル形式の読み込み

## 作り方（決定事項）

- 言語は Swift。macOS の InputMethodKit で IME を作る
- 変換エンジンと辞書は [AzooKeyKanaKanjiConverter](https://github.com/azooKey/AzooKeyKanaKanjiConverter) を Swift Package として使う（デフォルト辞書付きのプロダクト）
  - mozc 本体の組み込みは、Bazel と Qt が前提でエンジンだけをライブラリとして取り出す手段がなく、C++ との境界も自前になるため採らない
  - 1.0 未満で、マイナーバージョンが上がると API が変わることがある。バージョンは固定する
- Zenzai（ニューラル変換）を使う。初期値はオン。Apple Silicon の GPU（Metal）で動かす。モデルは azooKey-Desktop と同じく小さいものをアプリに同梱する
- 実装の手本は [azooKey-Desktop](https://github.com/azooKey/azooKey-Desktop)（MIT）。エンジンの組み込み方、Zenzai モデルの同梱、InputMethodKit まわり、署名、インストール手順を参考にする。ただし azooKey-Desktop はライブ変換前提なので、変換中のふるまいは本設計書に従って作る
- 名前は Momiji
- Xcode の Personal Team で署名し、自分の Mac にローカルインストールする。手順は azooKey-Desktop の `install.sh` にならう（ビルド → `~/Library/Input Methods` に配置 → ログインし直して入力ソースに追加）

## 状態とふるまい

IME の状態は大きく次の3つ。

Momiji は「ひらがな」の入力モードだけを持ち、英数モードは持たない。英字を打つときは、OS の入力ソースを Ctrl+Space で ABC（Dvorak）に切り替える。キーボードは US 配列で、Karabiner-Elements を使っている。

| 状態 | 説明 |
| --- | --- |
| 入力中（Composition） | ローマ字をかなにしながら打っている。下線付きの未確定文字列がある。自動サジェストが出ていることがある |
| 変換中（Conversion） | スペースで変換した後。文節ごとに区切られ、注目文節がある。候補ウィンドウはまだ出ていない |
| 候補選択中 | 候補ウィンドウが出ている。ホームポジションのキーで選べる |

### ホームポジションでの候補選択

- 候補ウィンドウが出ている間だけ、ホームポジションの10キーを候補の1〜10番目に割り当てる。押すとその候補で即確定する
  - Dvorak: `a o e u i d h t n s`
  - QWERTY: `a s d f g h j k l ;`
- 数字キー `1`〜`0` でも同じように選べて即確定する
- 「即確定」は mozc で数字キーを押したときと同じ動きにする（選んだ候補を注目文節に入れて、未確定文字列全体を確定する）
- 候補ウィンドウが出ていないとき（入力中、スペース1回目のインライン変換中、自動サジェスト表示中）は、これらのキーは普通に文字として入力される
- キーの判定は物理キーの位置ではなく、入力された文字で行う。OS 側で Dvorak 配列を使っているので、Dvorak の `a o e u i …` はその文字として届く
- 候補ウィンドウ表示中に選択キー・数字キー・操作キー以外の文字を打ったときは、mozc と同じく今の候補で確定してから次の入力を始める（私の判断）
- 候補ウィンドウが出るきっかけ:
  - 変換中にもう一度スペース（mozc と同じく、スペース2回目で候補ウィンドウ）
  - 入力中に Tab（予測変換）
  - 自動サジェスト表示中に Tab か ↓

### 候補ウィンドウの見た目

- 縦並び。各候補の左に選択キーを1文字表示する（Dvorak なら `a` `o` `e` …）。数字は表示しない
- 1ページ10件。右下にページ番号（例: `1 / 3`）
- 選択中の候補をハイライトする
- 未確定文字列の近く（カーソル位置の下）に出す

### 予測変換と自動サジェスト

- 入力中は、打つたびに予測候補を小さなサジェストウィンドウに自動で出す。サジェスト表示中も `a` `o` `e` などは文字として入力される
- Tab（または自動サジェスト表示中の ↓）で予測候補を候補ウィンドウに出す。そこからはホームポジションのキーで選んで即確定できる
- 打鍵に表示が追いつかないときは、サジェストだけ Zenzai を使わないなどで速さを確保する（調整方法は実装者に任せる）

### キー操作

mozc の [ことえり風キー設定 `kotoeri.tsv`](https://github.com/google/mozc/blob/master/src/data/keymap/kotoeri.tsv) の Composition・Conversion・Prediction の各行を、キー操作の仕様とする。特に毎日使うものは次のとおり。

- 文節の区切り直し: Shift+← / Shift+→
- 全角カタカナに変換: Option+X（Ctrl+K、F7 も同じ）
- そのほか: Space で変換・次候補、Enter で確定、Esc で取り消し、←→ で文節の移動、Option+Z／Ctrl+J／F6 でひらがな、Option+A／Ctrl+;／F8 で半角、Option+C／Ctrl+L／F9 で全角英数、Option+S／F10 で半角英数

`kotoeri.tsv` のうち、IME オン・オフ、英数キー（ToggleAlphanumericMode）、ReportBug など、英数モードを持たない Momiji や Mac で意味のない行、ノンゴールに関わる行は省いてよい。Option+キーも、物理キーではなく入力された文字で判定する。

### ローマ字テーブル

- Google日本語入力形式の TSV を読み込む。1行が「入力 ⇥ 出力」または「入力 ⇥ 出力 ⇥ 次の入力」。3列の行（例: `kk ⇥ っ ⇥ k`）にも対応する
- 対象は [dvorakjp-roman-table](https://github.com/shinespark/dvorakjp-roman-table) の `outputs/google_japanese_input/dvorak_jp.tsv`。これが正しく動くことを完了条件にする
  - このテーブルでは `;` を記号入力（`;h` → `←` など）や二重母音拡張（`ch;neru` など）に使う。入力中の `;` はテーブルどおり扱う。候補ウィンドウ表示中だけ QWERTY の選択キーとして使うので衝突しない
- 何も読み込んでいないときは、一般的なローマ字テーブルで動く
- 絵文字版（`dvorak_jp_with_emoji.tsv`）は同じ形式なので読み込めればよいが、全角記号を含む入力（`：ｔａｄａ` など）が動くことは必須にしない
- 読み込んだテーブルは Momiji 側に保存し、元ファイルを消しても使い続けられるようにする

### 設定画面

入力メニューの「設定…」から開くウィンドウ。項目は次の4つ。

- 選択キー: Dvorak / QWERTY
- ローマ字テーブル: 「ファイルから読み込む…」と「標準に戻す」。今使っているテーブルの名前を表示する
- Zenzai: オン / オフ（初期値オン）
- 自動サジェスト: オン / オフ（初期値オン）

変更は IME を再起動しなくても反映されるのが目標。

## 実装者に任せること

- プロジェクト構成（Xcode プロジェクトと Swift Package の分け方）、テストの構成
